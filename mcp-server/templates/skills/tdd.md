# /tdd - TDD実装手順

## Red-Green-Refactorサイクル

1. **Red**: 失敗するテストを書く
2. **Green**: テストをパスする最小限のコードを書く
3. **Refactor**: コードを整理する（テストは引き続きパス）

## TDD実装手順

1. 要件からテストケースを洗い出す
2. テストコードを先に書く（この時点でテストは失敗する）
3. テストをパスする実装コードを書く
4. テストがパスすることを確認
5. 必要に応じてリファクタリング
6. 完了報告

## TDDチェックリスト

- [ ] テストケースを洗い出したか？
- [ ] テストコードを先に書いたか？
- [ ] テストが失敗することを確認したか？
- [ ] 実装後にテストがパスするか？
- [ ] リファクタリング後もテストがパスするか？

## テストケースの考え方

### 正常系
- 主要なユースケースを網羅
- 代表的な入力パターン

### 異常系
- 不正な入力
- エラー条件
- 例外ケース

### 境界値
- 0, 1, max
- 空文字列, null
- リストの先頭・末尾

## 注意事項

- **テストなしで実装を進めることは禁止**
- strictモードでは `/strict-workflow` も参照
